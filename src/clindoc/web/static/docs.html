Overview

Clindoc2FHIR converts clinical documents (lab reports, medication order sheets and narrative discharge notes) into HL7 FHIR R4B bundles in which every element points back to the text and page region it came from. Each extracted fact is an atomic claim, for example Hematocrit: 46.1 % or Metformin dose: 500 mg. Before a claim is written to FHIR, a three-stage cascade checks it against its source evidence and gives it one of three verdicts:

  • SupportedThe source states the claim.
  • DiscrepancyThe source contradicts it: a different value, flag, unit, drug, dose, route or frequency.
  • Insufficient evidenceThe source does not say enough to decide either way.

A verdict measures document fidelity: whether the claim matches what the document says. It does not judge whether a value, drug or dose is clinically appropriate.

The web app has five working areas: the Workbench runs the whole pipeline on a document, the Playground verifies one hand-written claim, the Explorer replays the frozen benchmark verdicts, Results reports the benchmark numbers and Model shows Stage B model cards and live training progress.

Architecture

Five stages run in order. The evidence pointer (character offsets, page number, bounding box) created at extraction travels with each claim into the final FHIR resource.

  1. 1. Ingestion

    PyMuPDF reads born-digital PDFs into a DocumentText: pages, lines and words, each with a bounding box in PDF points (top-left origin). Scanned images and text-less PDFs need an OCR engine (the ocr extra, PaddleOCR); without one the API answers 422.

  2. 2. Extraction router

    A deterministic layout classifier (DEC-001) sends each region to one extractor. Every claim keeps an evidence span.

    • Deterministic parsersRow-level rules for lab result tables and medication order grids.
    • GLiNER-BioMedZero-shot entity extraction for unstructured medication text.
    • LLM narrative extractorSchema-constrained JSON from narrative notes; a mock provider stands in when no vLLM endpoint is configured.

  3. 3. Normalization

    • LOINCLab analyte names to LOINC codes.
    • RxNormDrug names to RxNorm concepts.
    • UCUMUnits to UCUM codes, with conversion (0.05 g to 50 mg) before any comparison.

  4. 4. Verification cascade

    • AStage A: DeterministicExact, numeric, unit and flag rules. Settles Tier 2 fields on its own.
    • BStage B: ModernBERTFine-tuned BioClinical-ModernBERT classifier with temperature-calibrated probabilities.
    • CStage C: LLM judgeQwen2.5-7B-Instruct-AWQ via vLLM, called only for escalated claims; returns a verdict and a rationale.

  5. 5. FHIR R4B bundle and audit report

    • FHIR R4B bundleDiagnosticReport and Observation for labs; MedicationRequest or MedicationStatement for medications (DEC-008), each with claim-provenance extensions.
    • DEC-016 audit reportStandalone JSON with every claim, its evidence, verdict, stage reached, confidence and rationale.

Verification cascade

The cascade is a selective classifier: cheap stages settle the claims they are sure about and pass the rest on. Fields are split into two tiers (DEC-019).

Field tiering (DEC-019)
TierFieldsStages
Tier 1, learnedlab.value, lab.flag, med.name, med.dose, med.route, med.frequencyA, then B, then C if escalated
Tier 2, deterministiclab.unit, lab.reference_range, lab.test_name, med.durationStage A only

When a Tier 1 claim escalates to Stage C

A claim is settled at Stage B only when Stage A and Stage B agree and Stage B's calibrated confidence is at least 0.60. It escalates when any of these holds:

  1. Stage A and Stage B disagree on the label (Stage A abstaining does not count as disagreement).
  2. Calibrated confidence is below 0.60, the DEC-005 operating threshold.
  3. Stage B predicts Insufficient evidence, which always escalates as a precaution.

Stage B confidence is calibrated by temperature scaling fitted on the calibration split only (DEC-009). Stage C returns a fixed confidence that is not calibrated (DEC-018), so treat its verdicts as decisions with a rationale rather than as probabilities.

Serving status matters: without a trained checkpoint Stage B runs a rule-based heuristic fallback, and without a vLLM endpoint Stage C is a deterministic mock judge. The status pill in the header shows which one is active; the Model page has the details.

Provenance (DEC-016)

Composite FHIR resources combine several claims that can carry different verdicts (a supported value with a discrepant unit, say). DEC-016 therefore attaches provenance at two levels, both using the extension URL http://clindoc.org/fhir/StructureDefinition/claim-provenance.

Running locally

Python 3.11 or 3.12. Run every command from the repository root: the pipeline reads data/ and schemas/ by relative path.

Install and start the web app 
git clone https://github.com/nobody294469/DAA.git
cd DAA
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[ml,web,dev]"     # add ocr to read scanned documents
clindoc serve                      # http://127.0.0.1:8000
clindoc serve options

Serve the real models 
export CLINDOC_VLLM_BASE_URL=http://gpu-host:8000/v1
export CLINDOC_VLLM_MODEL=Qwen/Qwen2.5-7B-Instruct-AWQ
clindoc serve --device cuda \
  --checkpoint data/m2_results_v3/checkpoints/modernbert_text_only_v3_fold0_seed42.pt

In PowerShell set variables with $env:CLINDOC_VLLM_BASE_URL = "http://gpu-host:8000/v1". The narrative extractor's LLM is configured in configs/extraction.yaml, not by these variables.

Training Stage B

scripts/train_v3_experiment.py fine-tunes BioClinical-ModernBERT on the V3 benchmark. Before training it checks the SHA-256 of the locked dataset files and that no document appears in two splits; temperature scaling is fitted on the calibration split only. The defaults reproduce the reference run in reports/M2_V3_MODERNBERT_TRAINING_REPORT.md.

Examples (repo root, package installed or PYTHONPATH=src) 
# End-to-end check: small subsets, 1 epoch, temp output dir, no model card
python scripts/train_v3_experiment.py --smoke --device cpu

# Reference run
python scripts/train_v3_experiment.py --device cuda

# Small GPU shared with another job
python scripts/train_v3_experiment.py --device cuda --run-name modernbert_v3_lowmem \
  --batch-size 8 --grad-accum 2 --gradient-checkpointing --gpu-mem-fraction 0.45

Outputs

  • <output-dir>/<run-name>_progress.json: live progress. The Model page follows it while the run is active.
  • <output-dir>/<run-name>_metrics.json: full validation, calibration and OOD metrics.
  • <output-dir>/checkpoints/<run-name>_fold0_seed<seed>.pt: the checkpoint. clindoc serve loads the newest one unless --checkpoint pins another.
  • reports/stage_b_runs/<run-name>.json: the small model card listed on the Model page (not written with --smoke or --no-model-card).

Verify one claim 
curl -s http://127.0.0.1:8000/api/verify \
  -H "Content-Type: application/json" \
  -d '{"field_type": "lab.value", "entity": "Hematocrit", "value": "46.1", "unit": "%",
       "evidence_text": "Hematocrit 46.1 % 36.0 - 48.0"}'

Returns final (label, confidence, stage reached, rationale), the rendered claim_text, the field tier, and stage_a, stage_b (with calibrated probabilities and escalation reason) and stage_c; a stage that did not run is null.

Process a sample or your own PDF 
curl -s -X POST http://127.0.0.1:8000/api/process -F sample_id=MED_0004
curl -s -X POST http://127.0.0.1:8000/api/process -F "file=@report.pdf" -F doc_type=lab

Returns the run ID, a verdict summary, per-stage counts, page images, every claim with its evidence and verification, the FHIR validation result and download links for the bundle and audit report.

Design decisions

Architecture decision records from docs/decisions. Locked decisions are final; open ones run on a provisional default until an experiment settles them.

Data contracts

JSON Schema files in schemas/ define what each pipeline stage hands to the next.

  • document_text.json

    Ingestion output: pages, lines, words and bounding boxes.

  • routing_decision.json

    Extraction router decision for each document region.

  • claim.json

    One atomic extracted claim, with its group ID (DEC-015) and canonical field type (DEC-017).

  • evidence.json

    Source evidence: text, character offsets, page and bounding box.

  • verification_result.json

    Cascade output for one claim (DEC-018, DEC-019).

  • audit_report.json

    Document-level DEC-016 audit report.

Limitations and safety

  • Not a medical deviceA research prototype, not clinically validated or approved for clinical decision support.
  • Fidelity, not clinical correctnessVerdicts say whether a claim matches its document. They do not assess appropriateness, contraindications or medical truth.
  • Synthetic benchmarkDocuments are rendered from Synthea patients with artificial degradation; no handwriting, carbon copies or real fax artefacts.
  • No external clinical benchmark yetEvaluation on n2c2 2018 Track 2 is gated on a data use agreement and credentialing.
  • Narrative extraction measured with a mock LLMThe standalone narrative benchmark (E3) used the mock provider; Qwen-7B was only evaluated inside the cascade.
  • Partial degradation matrixOCR degradation was evaluated in full on lab reports; the medication and narrative matrices were not run.
  • Variants not runV7 (OCR-aware ModernBERT), V11 (feature ablation) and the optional V13 (LoRA small LLM) were not executed.
